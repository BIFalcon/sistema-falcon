
- Indicadores DRE route, navigation and summary restrictions share dreAccess helpers; ADM-only access uses one linked hotel at a time and server DRE RPCs independently check hotel authorization.
- Novos Negocios uses DRE-specific read policies and can_read_dre_hotel, never general/global data-access helpers; its layout allows only DRE, indicators and account profile, and DRE resolution reads existing closings without creating them.
- Letter preview and download use requireLetterPdfBlob when live generation is configured; generation failures must surface instead of silently substituting a stored PDF.
- Letter DRE revenue composition uses letterRevenue keyed by the closing hotel ID; scoped templates prevent one hotel's line mapping from changing other hotels, and PDF rows must fit through distribution.
- Carta uses the authorized hotel list without persisted GOP scoping, defaults to a valid single hotel, and synchronizes direct closing links with shared filters; changing a filter releases the URL closing pin so the displayed letter follows the selection.
- RH monthly imports use rh_employees as the single source and import_rh_monthly as an atomic, serialized whole-period replacement; this prevents partial imports and keeps both RH panels consistent.
- Legacy payroll tables remain read-only historical fallbacks for periods without a consolidated upload; never combine both sources in the same period.
- Payroll RPCs retain the total_cost alias for compatibility, while consolidated values come from net_earnings; separate summary fields and an authorized overtime-history RPC preserve legacy/missing monetary data as NULL. payrollMetrics shares null-safe monthly series and ratio calculations with tests.
- RH payroll individual values are RH/Master-only through RLS and manager-checked RPCs; other authorized roles receive aggregates, never per-person costs.
- Use rhMonthlyParser for all new RH file reads and rhAccess for client permissions; server RPCs independently enforce permissions.
- Detailed payroll extras use nullable source columns and the versioned manager-only entries RPC; older layouts retain totals without fabricated detail. RH Roomnights uses an RH-authorized RPC reading the latest monthly DRE occupied-room indicator, not occupancy multiplied by cached availability.
- Turnover history uses independent authorized monthly snapshots, preserving event-time fields for period charts; departure reason categories are server-side aggregates so masked individual reasons remain private.
- Payroll sorting uses the pure payrollSort helper on copied rows, never mutating cache or export/access.
- Sensitive exports log to sensitive_export_log before the file is generated — reuse it for every sensitive export module.
- Consolidated RH departments are classified server-side by rh_department_for_position and a monthly-row trigger; this keeps individual and aggregate views consistent for current rows and future imports without changing legacy payroll data.

- Investidores module: all reads/writes go through SECURITY DEFINER `inv_*` RPCs (tables have RLS with no direct policies) so masking, audit (audit_access_logs) and finance notifications stay server-side; access comes from user_roles (edit + full view for editor roles) and user_permissions keys (finance, extra full view), never hardcoded e-mails.
- B2B settlement (Baixa) lives in conc_b2b_receipts; matching runs in the conc_b2b_auto_match RPC (sale×receipt by reservation locator, deposit×bank by net value+nearest date) and the bank description prefix is centralized in src/lib/b2bBaixa.ts so it can be adjusted once validated.
- Subdirectories have their own AGENTS.md (e.g. src/components/conciliacao) — read it before changing files there.
- Boleto settlement validates complete daily Francesinha totals through authorized server RPCs, stores invoice-to-bank lineage, and uses the bank credit date for automatic payment; paid verification accepts this lineage rather than comparing each invoice with an aggregated credit.
- Opera classification stores routing separately from the OMIE label and normalized matching key; database triggers synchronize TRX mapping changes and the reconciliation RPC independently uses routing to isolate card, PIX and cash flows.
- Post-import reconciliation repeats the complete authorized RPC until a zero-change pass, including receipt N:1; failures remain visible without marking the saved upload as failed.
- Rede sales parsing rejects expired PIX before the cancellation exception, so unpaid expired requests cannot become reconciliation sales while card adjustment imports remain intact.
- Daily bank closing uses server-maintained credit transit cycles and account/date snapshots; unnamed accounts alias only a hotel's sole named account, named snapshots take precedence without double counting, and initial balances use the latest earlier real snapshot.
- Conciliation divergence items and Home counts use authorized hotel-scoped RPCs; email enqueues reuse enqueue_ar_notification for linked GG/ADM, while their direct-link view exposes only conc_justifications, not reconciliation writes.
- Financial report upload controls live exclusively under the dedicated financial imports route, reusing existing ingestion hooks and per-report permissions; AR exposes settlement and TRX views separately to avoid duplicate ingestion paths.
- Selected divergence emails validate origin-qualified item IDs and derive all details and totals through authorized server RPCs; bank PIX detection stays equivalent in the shared client helper and server predicate to keep reconciliation, divergence lists and counts consistent.
- Performance interactions use the read-only get_closing_interactions RPC with server authorization matching canViewPerformanceSla; per-month React Query caches feed all front-end summaries, charts and exports without fetching event logs, and closingInteractions centralizes strict endpoint validity and unweighted statistics.
- System alert reads and resolution use useSystemAlerts: show the full pending count independently of the visible limit and verify the updated row before confirming resolution, so older replacement alerts and silent failures cannot look like ignored clicks. Resolving an alert does not resend email or remove provider suppression.
- Rede reimports deduplicate against every existing entry, including missing NSUs, and enrich all stable-key matches independently of delta classification; this preserves original identities and Opera matches while repairing missing report fields.
- Closing stage approvals are enforced by closing_stage_can_act (DB trigger) mirrored by canActOnStage on the client; a user with the fernando role (or the CEO e-mail) only acts at aguardando_fernando, even when also Master.
- DRE views are recorded only through the log_dre_view RPC (once per closing/version per session, counted again after 30 min).
- Hotel-specific net profit in Indicadores DRE comes only from NET_PROFIT_OVERRIDES (hotelNetProfit.ts, keyed by hotel_id) applied at dataset/history source, so every indicator view stays consistent; the DRE parser and Consolidado keep their own rules.
- RH Custo e Folha consolidated tab reads only the aggregated get_rh_payroll_consolidated RPC (reuses get_rh_payroll_summary per authorized hotel, gated by can_view_rh_consolidated mirrored by canViewRhConsolidated) so per-person costs never leave the per-hotel manager view.

- Investors: matrícula lives on units; payee fractions in unit_payee_shares (sum 100%, via inv_set_payee_shares); monthly payment batches snapshot Pool UHs × fractions and are re-checked before sending; CNAB 240 Itaú is built only by src/lib/cnab240Itau.ts (test-locked to the bank sample) and returns match by seu_numero.
- Startup installs domTranslationGuard before React; recover only detached-text operations inside the app root, preserving unrelated DOM errors, because browser translation can replace React-owned text. Static HTML declares pt-BR and disables translation.
- Recurring AR alerts use enqueue_ar_consolidated (one e-mail per recipient, all hotels) to avoid per-hotel floods.
