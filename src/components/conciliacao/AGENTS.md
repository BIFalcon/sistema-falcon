# Conciliação rules (also apply to related hooks, lib and SQL)

- Justification filters and Excel projection use conciliationJustifications; export reloads authorized hotel notes and joins by kind/side/entry ID so stale caches and unrelated notes cannot silently produce misleading spreadsheets.

- Rede receipts report (10 tabs) loads into conc_rede_pagamentos/recebidos/ajustes/chargebacks; bank settlement runs in conc_rede_auto_match against the aggregated recebidos, with bank prefix and brand/modality codes centralized in src/lib/redeRecebimentos.ts so the statement filter is adjusted in one place.
- Settlement cutoffs are hotel/provider-scoped; original-sale classification and explicit reversible transitions use authorized server RPCs, with bank confirmations reusing transit triggers so history and daily balances remain consistent. Unknown-origin credits are never excluded by settlement date alone.
- Francesinha (bank boleto report) loads into conc_francesinha_entries; the operation→action mapping lives only in classifyFrancesinha (src/lib/francesinha.ts) and conc_francesinha_apply settles ar_to_invoice_entries by document number + amount, so a changed mapping needs no SQL change. Spreadsheet reads go through fixSheetRef because some bank exports declare a wrong sheet range.
- Opera XML identity uses hotel + TRX_NO; conc_import_opera serializes whole-file imports under invoker RLS, adopts only unambiguous legacy matches (date/code/amount/receipt/room), and rejects ambiguous or changed identities atomically to preserve real repeated transactions and reconciliations. TOTVS retains its document-based path.
- Rede/B2B bank settlement requires complete, unambiguous net batch coverage and every underlying sale linked to a balanced same-hotel Opera match; server guards and unmatch rechecks preserve transit cycles, while authorized batch details share the same lineage and explicit cutoff transitions remain separate.
- Rede deductions require explicit authorized component allocation, except routine adjustments (anticipation fee, POS rental, tariffs) that conc_auto_allocate_rede_routine links automatically only when their unallocated sum closes the gap exactly on a non-twin batch; chargebacks/cancellations stay manual; shared twin compositions and inferred anticipation tolerances cannot release individual receipts. Hotel bank-prefix rules are server-resolved, and every transit cycle uses an authorized identity-based detail RPC; PIX/cash confirmation validates the full selected sum atomically, while financial-income matches remain bank-only and undo disables automatic reapplication.
- Boleto settlement validates complete daily Francesinha totals through authorized server RPCs, stores invoice-to-bank lineage, and uses the bank credit date for automatic payment; paid verification accepts this lineage rather than comparing each invoice with an aggregated credit.
- Opera classification stores routing separately from the OMIE label and normalized matching key; database triggers synchronize TRX mapping changes and the reconciliation RPC independently uses routing to isolate card, PIX and cash flows.
- Post-import reconciliation repeats the complete authorized RPC until a zero-change pass, including receipt N:1; failures remain visible without marking the saved upload as failed.
- Rede sales parsing rejects expired PIX before the cancellation exception, so unpaid expired requests cannot become reconciliation sales while card adjustment imports remain intact.
- Daily bank closing uses server-maintained credit transit cycles and account/date snapshots; unnamed accounts alias only a hotel's sole named account, named snapshots take precedence without double counting, and initial balances use the latest earlier real snapshot.
- Card auto-reconcile checks both sides are unmatched before writing; never write provisional matched_at then undo, because undos fire settlement rechecks and caused statement timeouts.
- Undo uses the hotel-authorized atomic conc_undo_matches RPC; capture affected active Rede/B2B bank identities before deleting lineage, recheck only those identities once, and bypass card rechecks for PIX/cash. Never replace this with client-side multi-table writes or a hotel-history sweep.
